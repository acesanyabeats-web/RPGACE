A5 Phase 1 build: the lazy-inject gate that would have silently broken 4 panels
Aug 15 2026
Discipline catch — rule 1/3 doing their job
Prompt scopeActive task: A5 Phase 1, confirmed via AskUserQuestion — "Build Phase 1 now" (relocate Idea Bank/Beat Log/Corpus/Workshop UI entry points, zero backend change).
ObstacleThe obvious-looking Phase 1 fix — remove ideas/corpus/beatlog/workshop from researchTabs.TABS so Research Lab's own tab bar shrinks — would have silently broken all 4 panels. Real evidence, found before editing: beatLog/refCorpus/conidPot each gate their own _inject()/_injectIdeaBank() behind research:tab-active firing with that exact tab key — a deliberate July 23 performance fix (one of ~6 real contributors to a reported 12-23s post-login freeze). Remove the tab key and that hook never fires with that value again, so the panel would never be created at all, for anyone, ever.
ReasoningFull grep sweep (rule 3: grep before adding new UI behavior) across every reference to researchTabs.show/rpgace_research_tab/each panel's DOM id, before writing a single line, per rule 1 ("pull real source before editing... never guess at function internals"). Found a second, separate real risk in the same pass: taxtree-manual-btn inserts itself as a DOM SIBLING immediately before #cp-idea-bank/#beat-log-panel at inject time — physically relocating those panels into dashDeck popups (the pattern _openGaps/_openPipeline already use for other widgets) would have stranded that button, orphaned, with no anchor content around it.
SolutionTwo real fixes married into one plan: (1) don't physically relocate the panels — keep them where their owning modules already put them, and instead jump-and-scroll to them on demand (no risk to the sibling-insertion assumption); (2) each new "open X" function calls the owning module's inject function directly (beatLog._inject(), refCorpus._inject(), conidPot._injectIdeaBank()) on demand, preserving the exact same lazy/on-click-only behavior the July 23 performance fix relied on — just triggered by a real user click on the new card/button instead of a tab activation.
Resulting ruleNo new numbered rule — a direct, real worked example of already-standing rules 1 and 3 catching a regression before it shipped, logged here so the specific failure mode (lazy-inject hooks tied to a UI element about to be removed) is on record for the next session that touches this class of change.
