🐂The Minotaur Map

system_flow_map.md is written for the nerds — exact function names, exact Mermaid syntax, exact code terms. This page is its plain-language twin: the Minotaur is a real piece of information — a chat message, a book chapter, an idea worth teaching — carried like water down a river system. Tributaries are the places information enters. Rivers are the paths it's carried along. Estuaries are where several rivers meet and become one shared current. The sea is where it finally reaches Alex's screen. Every river below is a direct plain-language translation of one real Mermaid diagram — nothing here is invented separately from it, so the two documents can never quietly drift apart. The rivers read in real chronological order — the actual step-by-step journey a piece of information takes, start to finish: gate → orientation → the three entry rivers → judgment → article generation → review queue → self-awareness → Content Production Live → the Chronicles estuary → the Total System Gateway → the Oversight Rivers. Every dry riverbed (a planned, not-yet-built piece) lives inline inside the real river it would join, never in a separate appendix — and a connector at the foot of every river states exactly where its water flows next, so the whole page reads as one continuous system rather than isolated diagrams.

Shape key (matches Mermaid's own convention exactly)
Spring / river mouth — where information enters or finally exits
Chamber — a real place along the river where information is read, judged, or changed
Fork — a real yes/no decision the code actually makes
Reservoir — a Supabase table, where information is stored and can be drawn from later
Dry riverbed — planned, not yet dug (not built)
