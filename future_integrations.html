How this doc works

Only GREEN (verified built and live) items appear in the real oversight docs — patch_notes.html, manual.html, minotaur_map.html, interconnection_map.md, system_flow_map.md, ai_tooling_and_rules_map.md, oracleAppGrounding.SELF_KNOWLEDGE, smoke_test.html. Per Alex's own direct ask: those docs describe what's ACTUALLY TRUE, and a non-built idea sitting alongside real, shipped features made it harder to tell the two apart at a glance.

Structure — PLAN FIRST (Aug 23 2026, DD2). Alex's own words: "i want plans to be first category - main one, then it breaks down by what river and modules are touched based on galaxy map." So the page's top-level axis is the real ceo_plans row; the second axis is the real Galaxy Map river the item's work actually touches (ceo_plan_items.galaxy_river, backfilled with real evidence for every non-green item in DD1); the specific real modules are named on each card (ceo_plan_items.galaxy_modules). Colour is now just a per-item badge.

Each card also carries short Galaxy Map identifiers, so an item can be cross-referenced straight against the real map page and the app UI without reading any prose: a gold level tag (L0/L1/L2/L2.5/Current/Zoom/L5/L6 — the same 8 stops as the Galaxy Map's own level rail), teal dimension tags (the real Dimensions Matrix names — Externals, UI/Alex-Accessibility, Load, Decision/Human-Gate, Orchestrator↔OpenMontage — plus Logic, Supabase, Skills and Oversight Sync where those genuinely apply), and a facet tag (💉 infra = attaches a real resource; 🔗 inter = changes a real cross-unit relationship, matching galaxy_map.html's own L0 Infra/Inter choice). A tag is absent when the real evidence doesn't support one — an honest blank beats an invented classification, so most pure module-level UI work carries no facet tag at all.

This replaced a colour-first layout that had a real, confirmed bug. The old page fetched every ratified plan's items together and dumped them into ONE hardcoded group labelled "🌌 RPGACE Total Systems Galaxy Map" — which was correct when the Galaxy Map was the only live-fetched plan, and silently wrong the moment a second ratified plan existed. By Aug 23 2026 there were five, so real items from four other plans were being displayed under the wrong plan's name. Plan-first grouping makes that class of mislabeling structurally impossible: a card can only ever render inside the group built from its own plan_id.

Everything on this page above the "Loose ideas" section is live-fetched — nothing is hand-typed. The old page live-fetched only the Galaxy Map plan and hand-typed the Massive Expansion plan's cards as static HTML, so that plan's real Supabase status could silently diverge from what this page claimed. It did: A5 was flipped to green in Supabase while its static card here still read "Research Lab page confirmed fully intact, untouched," which was flatly false. A hand-authored snapshot can always be forgotten to re-sync; a live fetch against the same table /colourgradient itself reads from cannot go stale that way.

The colour vocabulary is unchanged (it moved from being the layout to being the badge): 🔵 Blue — an idea quickly written down, not yet a formal plan. 🔴 Red — a real, specified plan, not built yet. 🟡 Yellow — genuinely mid-build, real code exists but incomplete or unverified. 🟣 Purple — a real REGRESSION: this was genuinely Green at some earlier real check, and current evidence shows it's now broken. Purple is not the same as Red — Red never worked yet, Purple worked and stopped; a Purple item also gets a real row in error_log.html. When something reaches Green it graduates OUT of this doc (the query filters on status=neq.green, so this happens automatically the moment the Supabase row flips) and its real state lands in the appropriate tier doc instead.

Purple is the one deliberate exception to plan-first grouping — it renders as a single cross-plan section at the top, with each card carrying its own plan name. A regression is worth seeing immediately without opening five plan groups; carrying the plan name on the card means no context is lost, and rendering it only there means no item ever appears twice on the page.

The fetch deliberately does NOT filter on basis='ratified' (the old one did). Every plan is ratified today, so the filter changed nothing visible — but a future provisional/draft plan would have been silently invisible here, which is exactly the "the doc doesn't show the real state" failure this restructure exists to fix. Each plan group shows its own real basis and status instead, so a non-ratified plan is visible AND clearly labelled rather than hidden.
