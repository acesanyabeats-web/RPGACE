How this doc works

Only GREEN (verified built and live) items appear in the real oversight docs — patch_notes.html, manual.html, minotaur_map.html, interconnection_map.md, system_flow_map.md, ai_tooling_and_rules_map.md, oracleAppGrounding.SELF_KNOWLEDGE, smoke_test.html. Per Alex's own direct ask: those docs describe what's ACTUALLY TRUE, and a non-built idea sitting alongside real, shipped features made it harder to tell the two apart at a glance.

Everything else lives here, grouped by real commitment level: 🔵 Blue — an idea quickly written down, not yet a formal plan. 🔴 Red — a real, specified plan, not built yet. 🟡 Yellow — genuinely mid-build, real code exists but incomplete. 🟣 Purple (added Aug 13) — a real REGRESSION: this was genuinely Green at some earlier real check, and current evidence shows it's now broken. Purple is not the same as Red — Red never worked yet, Purple worked and stopped; a Purple item also gets a real row in error_log.html, since a regression is a real error to track, not just an unbuilt idea. When something reaches Green, it graduates OUT of this doc and INTO the real oversight docs — this doc should never describe something that's actually true right now.

Backed by the real Supabase datasheet ceo_plans/ceo_plan_items (part of `/CEO`'s Grounded Mode) — this HTML page is a snapshot rendering of that live data, refreshed whenever `/colourgradient`, `/paranoia`, or `/drift` runs and pushes a real finding, per Alex's own explicit ask ("future integrations on /paranoia and /drift against any file and push just generated").

Real Aug 13 grouping convention, standing going forward: a multi-step CEO plan (2+ `ceo_plan_items` sharing one `ceo_plans` row) renders as ONE labeled plan-group, each step its own explained subgroup card — never scattered loose cards mixed with unrelated items. Every other item is grouped by what it actually changes — a named river (matching `minotaur_map.html`/graphify's own real river names), a dashboard card, or an external connector — instead of a flat list under each color. When a new item is added, find its real river/card/connector home first; only create a new group label if it genuinely doesn't fit an existing one.
