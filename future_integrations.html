How this doc works

Only GREEN (verified built and live) items appear in the real oversight docs — patch_notes.html, manual.html, minotaur_map.html, interconnection_map.md, system_flow_map.md, ai_tooling_and_rules_map.md, oracleAppGrounding.SELF_KNOWLEDGE, smoke_test.html. Per Alex's own direct ask: those docs describe what's ACTUALLY TRUE, and a non-built idea sitting alongside real, shipped features made it harder to tell the two apart at a glance.

Everything else lives here, grouped by real commitment level: 🔵 Blue — an idea quickly written down, not yet a formal plan. 🔴 Red — a real, specified plan, not built yet. 🟡 Yellow — genuinely mid-build, real code exists but incomplete. When something reaches Green, it graduates OUT of this doc and INTO the real oversight docs — this doc should never describe something that's actually true right now.

Backed by the real Supabase datasheet ceo_plans/ceo_plan_items (part of `/CEO`'s Grounded Mode) — this HTML page is a snapshot rendering of that live data, refreshed whenever `/colourgradient`, `/paranoia`, or `/drift` runs and pushes a real finding, per Alex's own explicit ask ("future integrations on /paranoia and /drift against any file and push just generated").
