3) REAL PRICING ANSWER (claude-api skill invoked per its own mandatory
   trigger rule — never answered from memory)
------------------------------------------------------------------
Anthropic API pricing (cached 2026-06-24, this skill's own live table):
Sonnet 4.6 (RPGACE's real ground-worker model) = $3.00 input / $15.00
output per million tokens. Sonnet 5 = $3.00/$15.00 ($2/$10 intro through
2026-08-31). Opus 5/4.8/4.7/4.6 = $5/$25. Fable 5 = $10/$50. Haiku 4.5 =
$1/$5. Prompt caching: reads ~0.1x base input cost, writes 1.25x (5-min
TTL) or 2x (1-hour TTL).

Real facts, not guessed:
- An API key has NO monthly fee and NO tiered "upgrade." It's a
  credential against a Console account balance; every call draws down
  that balance per token actually used. There is no flat "£X/month" cost
  for the key itself.
- Multiple keys under the SAME Console account/org share the SAME
  balance — rotating keys only helps with per-key rate limits (RPM/TPM),
  not with an empty balance. Real extra capacity needs a genuinely
  separate account/org with its own separate payment method.
- "Upgrade a key for better output/speed of thinking" is not a real
  concept — output quality/reasoning comes from WHICH MODEL is called
  (Haiku -> Sonnet -> Opus -> Fable) and settings like extended-thinking
  budget, never from a tier on the key. Usage tiers (1-4) raise rate
  limits as spend/payment history grows — they don't make output smarter.
- Claude.ai Pro/Max (flat monthly subscription) and the Anthropic API
  (pay-per-token, billed via Console) are two separate products/billing
  systems. This session has no tool visibility into which one(s) Alex is
  actually on — he needs to check console.anthropic.com/settings/billing
  (API balance) and claude.ai/settings (Pro/Max) directly.
- The free lever already built and standing idle most of the time:
  oracle_fallback_queue + the daily "RPGACE Fallback Drain" Routine —
  this Claude Code session's own separate Claude access answering queued
  questions at zero extra Anthropic-API spend. Today's build (Part 4)
  turns this from an emergency-only mechanism into a real, everyday
  "scout now, get answered later for free" workflow.

4) /investor PERSONA — PROS/CONS ON THE API-COST-MANAGEMENT QUESTION
   (the actual deliverable Alex asked for under item 3)
------------------------------------------------------------------
Persona: a 300-IQ investor/entrepreneur, 10 startups built (several
past £50M), putting £1M into RPGACE for a 10M GBP net shareholder stake
within 3 years.

PROS of the current approach (Sonnet 4.6 pay-per-token + the free
Fallback lane, no extra keys/upgrade purchase):
- Real cost discipline already exists and is documented (rule 11, the
  £10-burned-in-one-session audit, the 3-tier model system). A founder
  who already tracks unit cost per API call is a real diligence
  positive, not a nice-to-have — most solo AI-product founders don't.
- The free Fallback lane is a genuinely underused asset. It converts
  "I'm out of credits" from a stop condition into a batching decision —
  zero marginal cost, reusing infrastructure that already exists
  (the Morning Brief Routine's own proven pattern). That's real, already-
  built leverage most seed-stage AI tools don't have.
- Not buying a second API account avoids a real trap: founders who
  throw money at infrastructure before there's a proven revenue loop
  are a classic early-stage failure pattern this persona has seen
  repeatedly. There is currently ZERO confirmed revenue event in RPGACE
  (no beat sold via the Beatstars flow has been confirmed, no video
  posted end-to-end) — spending more on API capacity ahead of that is
  optimizing a cost line that revenue hasn't validated yet.

CONS / real risk:
- The Fallback lane is genuinely NOT live-chat capable (hourly-minimum
  trigger interval, batch by design) — if Alex's actual bottleneck is
  "I need Oracle NOW during a live session and it's down," this doesn't
  solve that; it solves "I want to keep working async." Conflating the
  two would be a real planning mistake.
- A single Anthropic Console account/payment method is a real single
  point of failure for anything revenue-facing later (e.g. an automated
  captioning/posting pipeline that MUST run reliably) — worth revisiting
  once there's an actual revenue stream depending on API uptime, not now.
- "How much is the API key a month" being an open question this late
  signals billing hasn't been actively monitored — worth a five-minute
  actual Console check (spend this month, current balance, auto-reload
  setting) rather than continuing to reason about it abstractly.

VERDICT (this persona, stated plainly): Not worth buying a second key or
chasing a nonexistent "upgrade" yet — that's spend without a validated
revenue reason. The real next commercial move is smaller and cheaper:
use the free Fallback lane for real, get ONE real revenue event
confirmed (a Beatstars sale, one video actually posted end-to-end), THEN
revisit infra spend with actual unit economics instead of guesses. This
is exactly the same conclusion CLAUDE.md's own governing rule already
points to ("does this result in a beat made or video posted within 48
hours") — the investor lens didn't change the answer, it gave it a real
business justification.
