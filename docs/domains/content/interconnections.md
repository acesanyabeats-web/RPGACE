## OpenMontage handoff lane — `openmontage_jobs`

A second external-session channel, structurally the same shape as the fallback lane above but pointed at a different consumer: `openmontage_jobs` is an async queue between RPGACE's Oracle, this Claude Code session, and a **separate** OpenMontage Claude Code session in a different repo (`add_repo` refuses to attach it here — a session is permanently tied to its starting repo's owner). A job carries a Visual Treatment brief plus the beat's real `beat_meta`; the external session picks it up, renders or refuses, and writes `status`/`output_note` back so both sessions share one timeline. **RLS posture is deliberate and load-bearing**: `anon_all`, because the external session writes back with the plain anon key and has no service-role key or `RPGACE_API_SECRET` — same standing exclusion as `oracle_fallback_queue`, and this table must never be swept into an RLS-restriction batch without first giving that session another way to write. OpenMontage stays an externally-operated tool; it has no embedded flow inside RPGACE.

**The feeding mechanism now (PC-2, Oct 17 2026):** `postingHub.logic.handoff` inserts the `openmontage_jobs` row (plan hook/story/shots + the beat's `beat_meta`, `requested_by:'rpgace_posting'`) from a beat-video post's plan screen; the old Production Panel Phase 4 path (`contentProductionLive._generateVideo` / `_buildVideoPipelinePayload`) was removed in PC-6.

**Additive columns, no RLS change**: `source_audio_url` (text) and `revision_notes` (jsonb, default `[]`). `source_audio_url` is RPGACE's durable record of the real song a job should sync to (the cinematic pipeline sources its own stock music by default otherwise). `revision_notes` carries per-scene redo requests for a documented (not schema-enforced — `status` has no CHECK constraint) `revision_requested` convention, supporting a pre-authorize-full-run-then-request-specific-scene-revisions pattern that fits OpenMontage's real approval model (Backlot is read-only; live chat reply or an explicit pre-authorization `decision_log` entry are the only real approval channels) better than per-scene live gating would. No client code writes to this table yet — every row so far was created manually by a Claude Code session.
