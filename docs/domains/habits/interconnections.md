**🍳 Cooking screens + stock loop** (`cookingOracle`, Oct 14 2026, Cooking Reorganisation) — `ui._wrapScreens` (run from `init`) wraps each screen in `ui.NAV_LABELS`, records it in `self._trail`, and `ui._decorateWhenOpen` re-points that `dashDeck._popup`'s `.dd-pop-nav` ← Back at the previous Cooking screen (re-invoked with its own args, or just closed if it's still open underneath) and adds 🏠 Cooking; opening the hub resets the trail. Stock writes: `logic._upsertStock` SETS a (ingredient, location) row (fridge photo, Current Stock form); `logic._addStock` ADDS to one (bought items via `logic._recordPurchase`, undo); `_loadPantryNamed` is a flattening of `_loadPantrySummed` (one read). Every finish path ends in `logic._finishCook` (hub, Live Cook, My Day cooking block, and `completeScheduledTask` → `ui._offerStockUpdate`), which calls `ui._offerStockUpdate` → `logic._planDeduction` (`recipe_ingredients` + `pantry_stock`, unit bridges via `logic._toStockUnit`) → confirm → `logic._applyDeduction` (writes `planned_cooks.stock_deducted`, never twice) → `logic._undoDeduction` / `logic._addToTopUpList` (`shopping_lists.kind='topup'`, deduped by unbought ingredient). Cook Mode's `onDone` asks to finish a planned cook (`ui._askFinishCook`) or offers a scaled stock update for a single saved recipe. `logic._generateShoppingList` now sets `shopping_lists.planned_cook_id`.

**🍽 Cook Mode ending** (`cookingOracle`, Oct 15 2026, CM-1/CM-2) — `ui._openCookMode` hands its last Done `{ startedAt, endedAt, clearProgress }` (start kept per key in localStorage) to `ui._askCookOutcome`, the one ending for every Cook Mode entry point. Actual cook on a planned cook → `logic._finishCook(..., { instant: true })`; otherwise `logic._recordUnplannedCook` inserts a `planned_cooks` row already `cooked` (the `xp_on_change` trigger awards Chef XP), writes a completed `rpgace_agendas` entry via the shared `scheduleToCalendar` (new `completed`/`started_at`/`ended_at`/`actual_mins` fields), then `logic._markJournalCooked` (shared with `_finishCook`) and `logic._dropFromDraftSessions` (drafts only). Both routes reach `ui._offerStockUpdate(..., { instant: true })` → `ui._applyStockInstant` → the existing `_applyDeduction` + `_renderStockResult` (undo via `planned_cooks.stock_deducted`). Preview touches no data.

**⏱ Cook Mode timers** (`cookingOracle`, Oct 15 2026, CM-3) — the shared `ui._mkStepTimerControls` (recipe card, Live Cook panel, Cook Mode) only counts down `passive_duration_min`; hands-on minutes get no timer. Cook Mode's waiting steps start a timer and advance; running timers live in the overlay's `.cm-timer-bar` (stored under `rpgace_cookmode_<key>_timers`, cleared with the rest of the progress) and, when due, show the step's `timer_end` (new RECIPE_JSON field, clamped by `logic._sanitizeStepIngredientsUsed`) or the next step's instruction. Schedule blocks carry `activeMin`/`passiveMin`/`timerEnd`; `logic._blockTimes` reads them, treating older blocks' cooking/baking time as waiting.

**💬 Cook Mode Ask** (`cookingOracle`, Oct 15 2026, CM-4/CM-5) — `ui._openCookMode` builds its own Ask panel (`.cm-ask-panel`) that calls `window.callOracle(history, system, 400)` directly, the system line rebuilt per question from the open Cook Mode's own state (title, `steps[idx]`, `logic._stepAmountText` ingredients, the `.cm-timer-bar` timers, all step instructions); history lives only in that Cook Mode instance. It hides `oracleControl`'s `#oc-floating-btn` (and closes `#oc-overlay-panel`) on open and restores it in `teardown`. `logic._stepAmountText` is the one amount formatter for Cook Mode and `ui._renderStepIngredients` (0 → "take out").
