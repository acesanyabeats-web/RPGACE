Moved here from `interconnection_map.md` on Oct 28 2026 (CK-3/4, plan "Caps and Central Kit"); text unchanged. The root file keeps cross-domain sections and links here.

**🤖 App prompts via Orchestrator CC** (CC-2, Oct 21 2026) — `orchestratorCC.logic.queue({type,key,prompt,tier,maxTokens,context})` puts a background prompt into `oracle_fallback_queue` (context `{type,key,cc:true,…}`, one open row per type+key) when the switch is 🤖 and resolves false on 💳 so the caller makes its normal API call. Types register `{apply(answer,row), api(row)?}` via `registerType`: `bookworm_chapter_extract` (bookworm `_ccApply`/`_ccApi`; `_analyzeChapter` = `_extractPrompt` + `_afterExtract`, shared by both paths; `bookworm_chapters.cc_queued_at` marks the wait), `xp_week_challenges` (`xpSeason.logic.ccApplyChallenges` → `saveOracleSuggestions`), `xp_wrapped` (`saveWrappedText`). Answers come back through the one existing sweep, `phylumPath._checkFallbackAnswers` → `orchestratorCC.logic.resumeRow` (`parseAnswer`; a broken answer → `runApi`); the same sweep calls `sweepStale` (pending past `fallback_hours` → claimed `api_fallback` → `runApi`). CC answers with `scripts/intel_cc_worker.py jobs/job/answer`.

**🏆 XP ranks, gates, badges** (XP-3, Oct 13 2026) — `xp_award` calls `xp_check_unlocks()` after any new `xp_events` row; it recomputes gates (cooks/sales/gym runs/phyla/routine weeks/countries/Heart overdue gaps from `caught_up` events), titles, auto badges and season + career (4× `min_xp`) ranks from `xp_ladders`, inserting via `xp_unlock(key, kind, realm, name, season)` into `xp_unlocks` (`unique(key, season)`, season -1 = forever), then writes a progress snapshot to `xp_settings.progress`. Triggers: `xp_gym_pb` (gym_sets → `gym_pb`, one per exercise per session), `xp_settings_check` (only when `revenue_target` changes), `xp_claim_check` (a claimed `xp_unlocks` insert). All four tables private, allowlisted in `/api/data-write`. Client: `xpSeason.logic.loadTrophies` / `rankFor` (same rule as the DB) / `progressText` / `claim` / `setRevenueTarget`; `ui.openTrophies`; strips, Season page and card show rank names. `careerStatCard._fetchAll` reads `xp_unlocks` (type `unlock`, Chronicles Life section). `cookingOracle`: `RECIPE_JSON_SHAPE` asks for `cuisine`, `_saveRecipeRow` stores it, the recipe card edits it.

**📅 XP reports + was-it-done** (XP-4, Oct 13 2026) — `xp_on_delete()` marks same-week rows `pending_confirm`; `xpSeason.logic.answerPending(id, done)` updates `xp_events.status` to `active`/`removed` through `/api/data-write` with match `id=eq.X&status=eq.pending_confirm`, so a late tap after week close is a no-op. pg_cron job `xp-close-periods` (`5 0 * * *` UTC) calls `xp_close_periods()`: for each ended week (Mon–Sun, London) without a report it sets that week's pending rows `active`, inserts a `balance_bonus` event (`source_table='xp_weeks'`, Life realm, 50 for 5+ realms / 150 for 8+), then `xp_save_report(kind, start, end, label)` inserts one frozen `xp_reports` row (`unique(kind, period_start)`); then months, UK weather seasons (`xp_season_start`/`xp_season_label`) and years (`xp_year_of`: 0 before 2027-01-01), then `xp_check_unlocks()`. Client: `loadTrophies` also reads `xp_reports`; `logic.reportRows(r)` is the one renderer used by the Year page's `ui.openReport` and `careerStatCard._detailFor` (type `report`, season/year rows only, Chronicles Life section). User-facing "Season" is now "Year"; internal names (`xpSeason`, `seasonOf`, `xp_events.season`) are unchanged.

**🎯 XP challenges, resolutions, realm quests** (XP-5, Oct 13 2026) — one table `xp_challenges` (kind `weekly`/`resolution`/`realm_quest`, `metric_actions` text[] — null = hand-ticked, `['realm_xp']` = sum realm XP; `step_key` unique for quest steps) plus `xp_quest_steps` (24 rows, 3 per gate, `progress_key` into `xp_settings.progress`). `xp_check_unlocks()` ends with `xp_update_challenges()` (counts `xp_events` actions in the period, pays `challenge_done` 75 / `resolution_kept` via `xp_award`) and `xp_quest_check()` (`realm_quest_step` 50). Trigger `xp_challenge_change` recounts a row when it becomes active and pays a hand-ticked done. `xp_close_periods()` marks active weekly → missed, suggested → expired at week close and active resolutions → missed at season close; `xp_save_report` data includes `challenges`. Client: `xpSeason.loadTrophies` reads both tables; `logic.openChallengePicker` merges `oracleSuggestions` (one `phylumPath.logic._callGroundWorkerJSON` call per week, realm totals only, saved as `suggested` rows and reused) with `ruleSuggestions`; `startChallenges` updates suggested→active or inserts via `RPGACE.sb.secureWrite`. `dashDeck` Due reads the week's challenges and nudges below 3; `careerStatCard` shows done rows as type `challenge` (Life). `logic.ukSeason` mirrors the DB `xp_season_start`.

**🎆 Year Wrapped + Hall of Seasons** (XP-8, Oct 14 2026) — `xp_save_report()` adds `treats`, `best_week`, `outreach` to every saved report; `xp_reports.wrapped_text`/`wrapped_seen_at` hold the one Oracle paragraph and the pop-up marker. `xpSeason.logic.wrappedFromReport` (closed year) and `wrappedLive` (current year, from `xp_events` + `loadTrophies`) produce one shape that `wrappedCards` turns into cards and `ui.openWrapped` renders as a `dashDeck._popup` swipe stage. `logic.ensureWrappedText` makes the single `phylumPath.logic._callGroundWorkerJSON` call (numbers only) and saves with match `wrapped_text=is.null`; `ui.autoWrapped` (from `renderCard`) and `ui.openWrappedReport` set `wrapped_seen_at`. The Trophy cabinet's Hall of Seasons (`ui._hallSection`, `logic.hallRows`) replaces the old Past years list. `dashDeck`'s Due list adds `logic.yearDue(today)` as promise r[12] (Wrapped ready, January resolutions nudge, missing year report).

**📜 Chronicles sections** (LL-8, Oct 13 2026) — `chroniclesLog.SECTIONS` (8 entries, each a list of item types; `all` has none) replaces the old flat `FILTERS`/`FILTER_LABELS`; `_renderFilterChips` shows per-section counts from `_allItems` and `_renderList` keeps items whose `type` is in the active section. `careerStatCard.logic._fetchAll` adds a 13th source, `plans` with `status=eq.done`, through `tripPlans.logic.read` (private proxy, empty before sign-in), then one `recipes?id=in.(...)` lookup for every finished cook's `recipe_ids`, returned as `data.recipeTitles`. `_buildItems` labels cooks via `_cookNames` (missing recipes fall back to the count) and adds `type:'trip'` items; `_detailFor` has matching trip and cook popups. The dashboard Chronicles preview shares `_buildItems`, so it shows the same labels. No XP weight reads these items.

**🌌 Realm cards** (`xpSeason`, Oct 14 2026) — `xpSeason.ui.hudFor(page)` (on `page:show`) shows the global `.char-header` HUD on the dashboard only. `ui.buildHud` rebuilds that HUD once into a 2-page scroll-snap track (page 1 keeps the legacy ids `#char-title`/`#lvl-display`/`#xp-bar`/`#xp-val`/`#stat-*` that older code still writes; page 2 holds `ui.wheel`), styles injected as `#xp-hud-css`. `ui.strip(realms)` — called by `dashDeck._popup` via `ui.popupStrip(cardKey)` (`CARD_REALMS`, now incl. `health`) and by `ui.pageStrip(name)` (`PAGE_REALMS`) — renders a `.char-header.xp-rc-card` in the HUD's own classes via `ui.realmCardHtml` (rank from `logic.realmRanks`, bar from `rankFor`'s `from`→`next.need`, pace from `logic.pace`); several realms get `.xp-rc-tabs`, starting on `ui.pickRealm` (worst pace first).

## The Chronicles — shared aggregation across `system_updates` + app tables

`careerStatCard` and `chroniclesLog` both consume one shared `_fetchAll()`/`_buildItems()` pair — the dashboard preview and the full log page can never drift on what counts as an "item." Every item, regardless of source table, normalizes to `{t, icon, label, type, row}` and routes through one shared detail-popup renderer (`_detailFor`/`_showDetail`, itself reusing `dashDeck._popup`). `chronicles_finance` (real sale/expense rows, personal-visibility only) and `system_updates` (Claude Code's own real changes to RPGACE) feed the same pipeline as Alex's in-app activity — one shared timeline, not two records. `bookworm_chapters` is excluded from the streak/recent-activity date logic (bulk-insert timestamp, not real completion time) and `chronicles_finance` from the XP/Level score itself — both deliberate exclusions.
