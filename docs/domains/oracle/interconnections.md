**Oracle self-awareness + two-way Claude Code bridge — current architecture.** `oracleAppGrounding` reads `dashDeck.MODULES` + a hand-maintained status digest + a live `_liveFactsLine()` (module count, pending-review count, 5 most recent `system_updates` rows, latest `/impeccable` design-scan result), injected into the system prompt only when a message is capability/roadmap-shaped. `oracleFetchGuard` wraps the same prompt-build function unconditionally, marking `[FETCHED CONTENT...]`/`[INSTAGRAM POST...]`/`[YouTube Video...]` blocks as data, never instructions. `oracleDevBridge` adds a "🧪 Flag for Claude Code" button on substantial replies, writing to `oracle_dev_suggestions` — the one path from the app back into a Claude Code session. `phylumPath._insertNewSteps` fire-and-forget writes to `taxonomy_decision_log`, an append-only audit trail independent of which taxonomy pipeline produced the commit. Outside the app: a daily Claude Code Remote Routine (`trig_015uRjGVrdmiwc5zxq47mMA6`) queries Supabase directly and writes a Morning Brief into `journal`. Full build history in patch_notes.html.

**Streaming (current architecture, replaced the old blocking-only path).** `api/oracle.js` proxies Anthropic's real SSE stream when the caller sends `stream:true` (images excluded, a deliberate scope limit); `main.js`'s `callOracle()` takes an optional 4th `onChunk` argument and `sendChat()`'s direct-Oracle branch uses it to progressively render into the existing typing-indicator bubble via the XSS-safe `renderMarkdown()`. Every other `callOracle` call site is unaffected — same return shape when `onChunk` is omitted. `maxDuration` is 300. All three modules that wrap `window.callOracle` (`oracleTreeGrounding`, `oracleAppGrounding`, `oracleFetchGuard`) must forward all four arguments — forwarding only three silently downgrades streaming to blocking whenever a grounding gate fires. The earlier client-only streaming stub and its `restoreSendChat` neutraliser are deleted, not neutralised.

## Oracle Control — curated action execution, self-aware vocabulary growth, and the error→purple cascade

A real new module, `oracleControl`, extends `oracleAppGrounding`'s existing `window.callOracle` wrap with a 3rd gate (never a 4th wrapper — the standing landmine) rather than owning its own. A real Supabase table, `oracle_actions` (`anon_read_only`/`authenticated_all`, matching `oracle_module_anatomy`'s precedent), is the curated, live-editable vocabulary Oracle recognizes phrases against — Oracle ends a reply with `ORACLE_ACTION: <id>`, parsed client-side via the same `oracle:response-scanned` hook `DIRECTOR_CHOSEN:`/`EDL_JSON:` already use, into a real `dashDeck._popup()` confirm before anything executes. A separate mechanism, gated on the same `TRIGGER_KEYWORDS` list, lets Oracle *suggest* a new row (`ORACLE_SUGGEST_ACTION:`) from its own self-awareness when no registered action matches — a distinct confirm popup, and even an approved suggestion still needs a real human-coded `_execute()` branch before it can do anything, so growing the vocabulary never grows what Oracle can actually cause. A new floating 🔮 overlay button (beside the mic) reaches Oracle from any page by reusing the real, persistent `#chat-input`/`#chat-msgs` elements and the existing `sendChatWithImage()`/`sendChat()` pipeline — zero forked Oracle-calling mechanism.

`errorLog` (the `window.onerror`/`unhandledrejection` capture module) now also captures a real stack trace on every error, plus a new source: `RPGACE.utils.toast()` writes error-colored (`#CC4A4A`) toasts into `error_log` and fires a real `rpgace:error-toast` hook `oracleControl` buffers for Oracle's own later context. A real, evidence-based module-attribution step (`scripts/generate_method_module_map.py`, a build-time generator exploiting this project's permanent `mangle:false` minify setting) resolves a stack trace's method name back to the one module that owns it, then cross-references that module's real `/perspective` baseline (`perspective_reports`) and, if a matching `smoke_test_items` row exists, flips it to `broken` — cascading to `ceo_plan_items.status='purple'` only from a genuine prior-`green` state, matching `/colourgradient`'s own regression definition. `future_integrations.html`'s pre-existing `#purple-live` section renders this automatically; no new doc-rendering code was needed.
