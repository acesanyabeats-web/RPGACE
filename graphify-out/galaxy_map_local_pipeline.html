The governing logic — what actually joins them

One stage per real step present in the source. This is the "logic attached" half of G110's own ratified scope: the cluster is not just three names, it is one ordered pipeline.

1Browser asks for an analysis

A real POST to http://localhost:7842/analyse with a URL. local_server.py does NOT analyse it inline — it writes an intel_jobs row with status:"queued" and returns immediately.

📄 local_server.py do_POST() → sb_post("intel_jobs", {...})
2The local poller picks the job up

A real background poll_loop() inside local_server.py watches Supabase for queued rows, marks one processing, and calls process_job(). This is why the whole pipeline is invisible to the deployed app: nothing on Vercel drives it.

📄 local_server.py poll_loop() → process_job()
3rpgace_intel takes over, with Alex's own API key

process_job() imports rpgace_intel as a module and sets intel.ANTHROPIC_KEY from ~/.anthropic_key. Progress strings are PATCHed back onto the same intel_jobs row so the browser can show them.

📄 local_server.py process_job() → rpgace_intel.process_url()
4Media in: metadata, download, transcript, frames

Real chain inside process_url(): get_metadata() (yt-dlp) → download_video() → Whisper transcribe_audio() → extract_frames() (FFmpeg).

📄 rpgace_intel.py get_metadata/download_video/transcribe_audio/extract_frames
5Judgement out: Claude Vision, then insights

analyse_frames() base64-encodes real extracted frames and sends them to Anthropic via call_claude(); generate_oracle_insights() then turns metadata + transcript + visual analysis into the real structured report.

📄 rpgace_intel.py analyse_frames() / generate_oracle_insights() → call_claude()
6Results land in Supabase and on local disk

Real writes: intel_reports and encyclopedia (via sb_post), intel_watchlist (via a real PATCH/POST), plus a real JSON file on Alex's own machine — which is why /reports still works when Supabase does not.

📄 rpgace_intel.py save_insight() / add_to_watchlist()
7The browser reads it back

3 real client fetch sites, all in rpgace_core.js's /* ===LEGACY:mainjs=== */ section: fetchFromLocal() → /reports, fetchWatchlistFromLocal() → /watchlist, pushLocalToSupabase() → /push-to-supabase. Reached from syncIntelData() (River XII's own 30s sync) and syncAndPush().

📄 rpgace_core.js syncIntelData() / syncAndPush()
