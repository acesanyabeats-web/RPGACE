The Governing Rule
"Does this feature directly result in a beat being made or a video posted within 48 hours of using it?"

Yes → build immediately. No → wait. Standing exception: RPGACE infrastructure work is exempt.

Architecture
Three Layers + Two Real Hubs
LAYER 1: main.js (FROZEN) — core rendering, chat, calendar, encyclopedia
LAYER 2: rpgace_core.js — all domain modules, via RPGACE.register()
LAYER 3: api/ (Vercel serverless) — oracle.js, intel.js, composio.js

The two real hubs everything converges on (confirmed via full interconnection audit): Oracle (Claude API, generation) and Taxonomy Tree (knowledge structure). Only the Schedule system runs fully independent of both — shifts, agendas, and calendar form a self-contained loop with no taxonomy dependency.

  1. py rpgace_build.py new DOMAIN moduleName
  2. Write logic in mod_moduleName.js
  3. py rpgace_build.py add DOMAIN mod_moduleName.js
  4. py rpgace_build.py check
  5. git add rpgace_core.js && git commit -m "..." && git push
  6. npx vercel --prod

Supabase Tables
RLS status — corrected July 31, and this correction matters. This section previously carried a July 23 finding stating that every table used a permissive USING(true) policy, "functionally readable/writable by anyone with the public key, project-wide." That has not been true since July 24, when the real RLS flip was executed and verified against Postgres's own pg_policy catalog. A fresh pg_policies query on July 31 confirms the current state: 18 tables are restricted (anon_read_only SELECT + authenticated_all — the anon key can read but cannot write; all writes route through /api/data-write's service-role proxy, itself gated by the shared secret), and 10 tables deliberately remain anon_all because each has a real external writer holding only the plain anon key. Those 10 are not an oversight and must not be swept into a future restriction batch without first giving that writer another way in: journal (Morning Brief Routine), oracle_fallback_queue (Fallback Drain Routine), openmontage_jobs (the separate OpenMontage Claude Code session), beat_audio_jobs (the local librosa runner), intel_jobs/intel_reports/intel_watchlist/intel_bibliography (local_server.py), rpgace_shifts (an external Python script), and system_updates (Claude Code sessions via MCP). Any per-row "RLS enabled, anon_all policy" note below records a table's creation-time posture; the two groups named here are the authoritative current state.
