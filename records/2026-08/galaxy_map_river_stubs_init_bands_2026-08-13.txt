PART 2 — NO `init` NODE AT LEVEL 3
---------------------------------------
compute_function_rank() no longer treats `init` as a forced depth-0
entry — its own real direct callees become the true depth-0 entries
instead (any OTHER function with genuinely zero real callers stays a
real entry too, unchanged). `init` still participates in depth
computation (so its callees land at the correct depth) but is filtered
out of rendering entirely. 43 of 44 real Level-3 modules have an
`init` — a real, meaningful fix, not a one-off.

Legend now explains what init actually is (real bootstrap plumbing —
boot-task registration, RPGACE.hooks wiring, page:show re-injection —
never called by real code inside the module, only by RPGACE.register()
's own external machinery) whenever a module has one.

Real pairing (Alex's own ask: "maybe pair with what comes from level 3
function in previous river if it makes sense") — reuses Part 1's exact
same attribution evidence: a new _incoming_attribution_for_module()
checks whether any real incoming river connection lands specifically
on one of THIS module's own functions; if so, that entry gets a real
"⬅ from River N" badge right on the node — a genuine, evidence-backed
stand-in for the removed init, not a generic label.

PART 3 — RANK-BAND SUB-PAGES (Alex-confirmed option)
---------------------------------------------------------
Real, cheap threshold: modules with >15 real functions get split.
Verified against real depth-distribution data before building (not
assumed even) — phylumPath/contentProductionLive/bookworm all spread
functions across many depth values rather than spiking at one, so
depth-range banding genuinely reduces node count per view (not just
theoretically). Bands balanced by real FUNCTION COUNT (not raw depth-
width) via a greedy accumulation over real depth buckets in order.
8 of 44 modules banded (beatLog, bookworm, contentProductionLive,
feynman, intelDelete, phylumPath, taxonomyTree, videoSummary) — the
other 36 render exactly as before, zero behavior change (real, cheap
early-return in _split_into_bands() when under threshold).

Real, substantial refactor: build_module_section()'s single-canvas
logic factored into a new _render_band() helper, called once per band.
Real cross-band edges (a function in Band 1 calling one in Band 2) are
NEVER silently dropped — a real dangling "↦ Band N: func" stub at the
sending band's own right edge, "⬅ Band N: func" at the receiving
band's own left edge, reusing the exact same visual language as the
river-connection stub (Part 1) and the existing backdoor gateway (same
established pattern, not invented fresh — rule 8). Alex bubble,
backdoor gateways, and the init-pairing badge are all scoped per-band
(honest — the counts shown reflect what's actually on screen in that
band, not a global module total).

Real bug caught before shipping: the new band-tab buttons were first
given the SAME `.tab` class as the existing top-level module switcher.
The existing JS reads `dataset.target` on every `.tab` click — a band-
tab only has `dataset.bandTarget`, so sharing the class would have set
`location.hash = undefined` on every band-tab click, silently breaking
navigation. Fixed with a distinct `.band-tab` class and its own,
separate click-handling JS block.
