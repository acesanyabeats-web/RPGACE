PART 2 — THE REAL LOAD-TIME AUDIT (static code analysis; live Lighthouse/
PageSpeed remains a confirmed-blocked path from inside this session per
CLAUDE.md's own Known landmines — not re-attempted)
================================================================

Real, measured evidence, not estimated:
- `rpgace_core.js`: 1,124,028 bytes raw, 308,862 bytes gzipped (`gzip -c |
  wc -c`), 19,749 lines, 4,145 of them (21%) comment lines (`grep -c
  '^\s*//'`).
- `main.js`: 257,090 bytes raw, 75,485 bytes gzipped, 4,397 lines, 442
  comment lines.
- Both loaded via plain blocking `<script src>` (no `defer`/`async`),
  positioned near the end of `<body>` (line 458 of 633 total — already
  good placement, not blocking initial paint), loaded sequentially
  (main.js then rpgace_core.js). Together ~1.38MB of JS parsed+executed
  before `rpgace:ready` fires.
- `vercel.json` had zero `headers` block before this pass — no explicit
  Cache-Control tuning for static JS/CSS/icons, relying entirely on
  Vercel's platform defaults.
- `index.html`'s Google Fonts `<link rel="stylesheet">` had no
  `preconnect`/`dns-prefetch` — a render-blocking external CSS fetch with
  a cold DNS/TLS handshake to `fonts.googleapis.com`.
- 31 `registerBootTask` calls found; 20 use `setTimeout` delays in the
  1300-1700ms range (the project's own documented convention, protecting
  against the `hooks.fire()` late-registration landmine — real, load-
  bearing design, not an oversight).

Real, applied fixes (safe, zero behavior risk, verified before shipping):
- Immutable 1-year caching on the 4 static-asset classes above — safe
  specifically because 3 of the 4 (`rpgace_core.js`, `main.js`, and now
  `style.css`) are query-string versioned; a cached URL's content
  genuinely never changes, a real content change always mints a new `?v=`
  URL. Icons never change without a filename bump (matches `sw.js`'s own
  existing precaching assumption).
- `style.css` version-string gap fixed BEFORE applying the header — real
  evidence-check caught this mid-implementation (it had zero `?v=` at
  all), preventing a new stale-CSS bug the header would otherwise have
  created.
- Preconnect hints for both Google Fonts domains.
- Deployed and confirmed `READY` on production (commit `c5fc54c`) before
  continuing to the rest of this pass.

Real, honestly NOT fixed this pass, both flagged as genuine open forks
rather than built blind or silently ignored:
- **Minification/comment-stripping of `rpgace_core.js`/`main.js`.** Real
  headroom (21% comment lines in the bigger file), but two real, specific
  risks named directly: (a) the zero-build-step architecture rule is
  explicit and load-bearing — any minifier would need to be a committed,
  hand-re-run repo-generation script (same shape as
  `scripts/graphify_recolor.py`), never a live Vercel build step; (b) this
  exact codebase has a standing, NAMED landmine about a naive text-
  transform corrupting shipped code (the `exportEncyclopedia` fake
  `</body></html>` string-literal trap, "never use Python string-replace
  on index.html") — a regex-based stripper risks the same class of bug
  unless it's a genuine JS-aware minifier (e.g. terser), which would be
  RPGACE's first-ever dev-time npm dependency. Needs Alex's explicit
  steer, not decided here.
- **The 1300-1700ms boot-task stagger.** Real, intentional design
  protecting against a documented race condition — but it also means
  many UI modules visibly appear over a second after the page is
  otherwise ready, real PERCEIVED latency distinct from raw bytes.
  Reducing/restructuring it is a genuine architecture question (could
  some modules safely inject earlier? does the 1300-1700ms range itself
  need to be that wide, or was it picked once and never revisited?), not
  a blind global speed-up.

--- GODMODE+scope+commit-archaeologist (real risk: does Grounded Mode
    violate rule 11, token/time cost discipline?) ---
Real risk named directly, not glossed over: "grounded to every prompt"
could be read as "run full `/drift` Steps 1-4 on every single message,"
which WOULD be a real rule-11 violation — a cheap typo-fix prompt does
not need a Supabase round-trip plus a drift analysis. Real mitigation
built into the CEO skill file itself: Grounded Mode is explicitly TWO-
TIERED — a cheap existence-check + relevance judgment on every prompt
(genuinely low-cost: one indexed SELECT, one judgment call), escalating
to the real `/drift` Steps 1-4 cost ONLY when a prompt actually touches a
plan item. An unrelated one-line fix costs one extra SELECT and nothing
else. This mirrors the Judgment Funnel's own tiering discipline
(CLAUDE.md's Tier 0-3), applied to a new recurring check rather than
inventing a separate cost model.

--- /debate — real tension worth naming plainly rather than hidden ---
Case FOR Grounded Mode running automatically: Alex's own stated problem
("keep larger goals in tact... chase long term goals") is real and
already evidenced this week (CLAUDE.md's own Aug 11 entry: an entire
session's real work was reported "shipped"/"live" while sitting unmerged
on a feature branch, caught only because Alex checked the live site
himself) — an automatic, cheap per-prompt check is a genuine structural
defense against exactly that failure class recurring, not ceremony for
its own sake. Case AGAINST always-on: a per-prompt check that's wrong
often enough (false-positive "this touches the plan" on genuinely
unrelated work) would itself become the annoyance rule 11 exists to
prevent, and a badly-calibrated relevance judgment is a real risk with no
current track record to validate it against. Resolution, not a forced
tie: ship Grounded Mode as specified (Alex's own explicit ask, not a
guess), but name this as the first thing to watch — if a future session's
relevance judgment turns out to be over-triggering on unrelated prompts,
that is real, concrete feedback for tightening the check, not evidence
the whole idea was wrong.
