REAL FORKS RESOLVED VIA AskUserQuestion (all 4, recommended options
confirmed):
1. Combine mechanism: SINGLE SHELL, LAZY-LOADED CONTENT — one new
   shell HTML becomes the one URL/gateway; the 21 existing files stay
   on disk as the real generated source, loaded into a content pane
   on demand (fetch+inject) rather than concatenated into one
   monolithic multi-megabyte file. Chosen specifically to avoid
   repeating the just-logged boot-lag regression.
2. Top-nav shape: GROUPED LIST + FLOW ARROWS — not a full graph-canvas
   landing page (mobile small-target/pan-zoom risk, this project's own
   standing "thumb-sized target" rule). Grouped by Level + cross-
   cutting dimension pages, each row annotated with a real "-> flows
   into X" line sourced from already-computed flow/terminal data.
3. Inter vs infra: PER-NODE BUBBLE, PER-EDGE SELECTOR ON SHARING —
   "inter" dimensions (river-flow, hook signals, cross-module calls,
   connection/flow-type pages) render/are treated as edges between
   things, same as already built. "Infra" dimensions (Supabase, Load,
   Oracle/Composio call-count bubbles, resource/attachment-type pages)
   attach to the ONE node/page that needs them — UNLESS that same
   infra is shared across 2+ different inter-edges at once, in which
   case it becomes a selectable option ON the edge (a toggle/dropdown
   to pick which infra applies) instead of a static bubble.
4. Build scope: NEW /CEO-TRACKED PLAN, PHASED — logged as new G-items,
   built in scoped passes with real checkpoints, not one giant
   unreviewable commit touching all 21 files' internals at once.

REAL PLAN, LOGGED AS ceo_plan_items G58-G60:
- G58 (umbrella): "Galaxy Map Unified Gateway" — the ask as a whole.
- G59 (this pass, built): the shell itself — a new central
  `graphify-out/galaxy_map_hub.html`. Real map/table toggle at the
  shell level: TABLE view = the grouped-list-with-flow-arrows (answers
  fork 2 directly); MAP view = a real node-link diagram of all 21
  pages as nodes, edges computed from real cross-references already
  present in each page's own HTML (grepped href targets between
  galaxy_map_*.html files — not invented). Every node carries a real
  🚪 entry-point or 🏁 terminal badge (reusing the existing convention,
  applied at the page grain: a page is an entry point if nothing else
  in the 21-page set links INTO it; a terminal if it links to nothing
  else in the set). Each row/node also carries an INTER (🔗 connection-
  type page) or INFRA (💉 resource-type page) classification — a real,
  evidence-based read of what each of the 21 pages actually represents,
  not a guess (see classification table in the build script itself).
  Clicking any entry loads that page's real content into a shared
  iframe content pane, without a full navigation — the 21 files
  themselves are UNTOUCHED, satisfying "one central html with gateways
  to each other" without the monolithic-load risk.
- G60 (logged, explicitly NOT built this pass): the deeper retrofit —
  applying the per-node-bubble/per-edge-selector infra/inter rule
  INSIDE each of the 21 existing pages' own rendering (i.e. wherever a
  page currently draws a Supabase/Oracle/Composio/Load bubble on a
  node that is genuinely shared by 2+ inter-edges, convert it to a
  real edge-selector instead of a static bubble). Large, touches many
  files, deliberately phased per Alex's own confirmed choice (fork 4).

WHAT THIS PASS DOES NOT DO (explicitly, not silently):
- Does not rewrite any of the 21 existing galaxy_map_*.html files'
  own internal rendering.
- Does not yet implement the edge-selector-for-shared-infra mechanic
  (that is G60).
- Does not remove the Oversight popup's existing 5 sub-groups of
  individual links — the new hub becomes the PRIMARY entry point,
  the individual links stay as a real secondary/direct-access path
  (never delete a working navigation path as a side effect of adding
  a new one).
