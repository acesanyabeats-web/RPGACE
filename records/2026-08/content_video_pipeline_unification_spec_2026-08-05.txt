THE CORE ARCHITECTURE VISION (Alex's own framing, condensed but not
substituted)
=====================================================================
Merge Log Beat, Live Content Production, Content Pipeline, and Video
Pipeline into one coherent flow, not 4 disconnected surfaces. Log Beat
gives Content Pipeline an idea to work on (music_video workflow); raw
OBS footage triggers the editor/tutorial workflow. Both workflows go
through DIFFERENT PROCESSES (because the inputs differ) but the SAME
STAGES in Content Pipeline (every video needs the same real steps from
raw to done, just implemented differently per input type). Oracle-saved
ideas (conid_pot) are one extra step before this: make the content for
the idea, then the output goes through the same system. Converting
conid_pot -> content_productions ("PotConID to ConID") is the real
gateway - Alex puts in his beat or raw OBS footage, the code recognises
which file type it is, and routes to the correct workflow.

REAL EVIDENCE CHECK (Aug 5): most of this already matches built
architecture - one shared content_productions table, content_type
discriminator ('tutorial'|'music_video'), same status column with
display-label overrides. What's NOT built: automatic file-type
detection at the gateway (currently Beat Log and Production Panel are
two separate explicit entry points Alex chooses between, not one
dropzone that auto-detects audio vs. video). Scope of the auto-detect
gateway itself was not separately interrogated this pass - flagged for
the build plan to confirm before implementing literally as "one
dropzone."
