2. THE REAL PLACEMENT MECHANISM (phylumPath._insertNewSteps,
   rpgace_core.js:9050) -- read in full. Critical finding: this
   function ONLY EVER INSERTS NEW ROWS. It takes an attachNode (an
   existing node an insight is being placed under) and a newSteps
   array (the NEW path segments below that attach point), and chain-
   inserts one fresh row per step, marking the LAST one 'leaf'. If
   newSteps is empty (meaning: "this insight belongs on an ALREADY-
   EXISTING leaf, no new node needed"), the function REJECTS outright
   ("Oracle returned no new steps to place this insight" --
   rpgace_core.js:9052). There is no code path anywhere in this
   function, or in _generateInsightContent (called once per newly-
   created finalRow only), that APPENDS a second insight onto an
   already-existing leaf's own content.

   REAL IMPLICATION: right now, every single placed insight mints at
   least one brand-new taxonomy_tree row. No leaf in this entire
   project has ever accumulated more than one insight's worth of
   content. Alex's ask -- "one txt list of insights... that insights
   have generated specific to this leaf" -- describes a genuinely NEW
   capability, not a tweak to an existing one. This is the single
   most important feasibility finding for the whole plan.

3. Existing content shape at a leaf: explainer (short string) +

   _generateNodeContent's 2-layer prompt, _generateInsightContent's

   THREE are a single field holding ONE piece of content, overwritten
   whole on any update (_updateExistingNode does `explainer:
   newExplainer` -- a straight overwrite, not an append).

4. taxonomy_decision_log (rpgace_core.js:9115) already exists and
