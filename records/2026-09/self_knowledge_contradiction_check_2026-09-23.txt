===========================================================================
WHAT WAS BUILT
===========================================================================
scripts/check_self_knowledge_contradictions.py -- a real, bounded,
zero-AI-cost mechanism, deliberately NOT a general fact-checker (that
would need a real AI call re-reading the whole string against the whole
codebase's actual behavior every session -- real token cost, rule 11, out
of scope for a per-session check).

What it DOES catch, mechanically: a NEGATIVE/ABSOLUTE claim ("zero
persistence", "not connected to", "does not exist"...) made near a real,
named module (`/* ===MODULE:name=== */` marker) or Supabase table (a real
`RPGACE.sb.insert/update/del/secureWrite('table', ...)` write-call
target), where the codebase's OWN current write evidence for that exact
entity now contradicts the claim. This is precisely the shape of the
Quest Board bug -- a claim anchored to a real identifier that a later
real code change silently falsified.

10 curated negation phrases (rule 7 -- never a broad fuzzy net): 'zero
persistence', 'no persistence', 'no real persistence', 'not connected
to', 'NOT connected', 'does not exist', 'DOES NOT exist', 'nowhere
persistent', 'has no real', 'has zero'.

Reuses `extract_self_knowledge()` from check_self_knowledge_staleness.py
(rule 8 -- one shared extractor, not re-derived).

===========================================================================
A REAL BUG FOUND AND FIXED DURING TESTING, NOT SHIPPED BLIND
===========================================================================
The first version's own real test run (against the just-rewritten, actual
current SELF_KNOWLEDGE content) produced 2 false-positive findings
(`questEngine` module, `quest_log` table) -- both from the SAME sentence,
the Sep 23 2026 fix's own real correcting text:

  "The Quest Board (addXP/completeQuest) now HAS real persistence via a
  dedicated questEngine module (built Aug 23-24 2026) - completions write
  real quest_log rows and boot-time restore re-derives XP/level/done-
  state from them; this corrects an old, wrong claim this string used to
  carry ("zero persistence") - never repeat that old claim, it has been
  false since Aug 24."

Root cause, found by direct diagnostic printing (not guessed): the
sentence quotes the RETRACTED old claim with DOUBLE quotes
("zero persistence"), not single quotes. The first version of
`strip_quoted_spans()` only stripped single-quoted spans
(`re.sub(r"'[^']*'", '', sentence)`) -- it never touched the double-quoted
span, so the negation-phrase check still saw 'zero persistence' sitting
right there and flagged the sentence, exactly the false-positive class
this function was built to prevent, just for the wrong quote character.

Real fix: `strip_quoted_spans()` now strips BOTH quote styles
(`'[^']*'` and `"[^"]*"`), applied in sequence. Re-ran the exact same
test after the fix: 0 findings, exit 0 -- confirmed via direct re-run,
not assumed from reading the diff.

===========================================================================
Honest, named scope limits (unchanged from the script's own docstring,
confirmed accurate by the regression test above, not just claimed)
===========================================================================
- Only catches a negative claim phrased near a REAL module/table
  identifier by name -- a claim about a bare function name alone (no
  module named nearby) is invisible to this mechanism, same as the
  original bug's own exact wording was.
- Only checks the 10 curated negation phrases -- a real wrong claim
  phrased without one of these exact markers is not caught.
- Only checks PERSISTENCE/CONNECTION/EXISTENCE-shaped claims, not every
  possible kind of factual error (a wrong NUMBER, a wrong DATE, a wrong
  causal claim between two real things -- none of these are in scope).
- This is a NEGATIVE-CONTRADICTION detector, not a general SELF_KNOWLEDGE
  correctness prover -- a clean run means "no known-shape contradiction
  found," never "SELF_KNOWLEDGE is fully accurate."
