=== PROPOSED DESIGN (not built — for review before any code changes) ===

**A. `EDGE_EVIDENCE`, a Python-side lookup built once in
graphify_river_group.py, keyed by the real `(from_label, to_label,
kind)` triple every `_curved_edge()` call site already has in scope:**

    EDGE_EVIDENCE: dict[(str, str, str), dict] mapping to
    {
      'explanation': str,   # full sentence, not a hover-truncated one
      'source': str,        # e.g. 'attribute_river_connection_function'
                             # or a file:line-shaped citation
      'zoom_href': str,     # real navigable URL+anchor
    }

    Populated per kind, from the sources already gathered above:
      - river_link / river_entry -> attribute_river_connection_
        function()'s own (module, function, signal) result, formatted
        into a real sentence ("River III connects to River XI via
        cookingOracle._dispatchToBeatLog(), a traced direct call.").
        zoom_href -> galaxy_map_current.html#mod-<module> (the real
        function's own Current(L3) anchor already computed elsewhere).
      - function_call / backdoor_call -> the matching
        compute_cross_module_function_calls() tuple, formatted
        directly ("beatLog._submit() calls dashDeck.refresh()
        directly."). zoom_href -> the CALLEE's own Current(L3) anchor
        (where the reader would go to see what actually runs).
      - skill_stream / dashboard_card / external_call / ui_input /
        ui_output / cross_band_call / dimension_membership /
        galaxy_link -> the matching build_infra_drilldown() (resource,
        detail) pair for that (module, func), already real text.
        zoom_href -> the Dimension/Infra page section that resource
        already belongs to (every one of these pages already computes
        its own real anchor ids for exactly this reason).
      - dispatch_trigger -> whichever detector already produced this
        edge (grep confirms it's a specific real call site; the design
        does not invent new evidence, it reads the one that's there).

    R22 extension, made literal and checkable: build a real
    `verify_edge_evidence_coverage()` companion (same family/shape as
    `gmp_b_consistency_check.py`/`galaxy_map_g13_onclick_coverage_
    check.py`, rule 8) that, at generation time, asserts EVERY edge
    any page draws has a matching EDGE_EVIDENCE entry for its own
    (from_label, to_label, kind) — an edge with none either doesn't
    render, or renders visibly `dashed` (the existing `_curved_edge`
    `dashed` param already means "no real evidence," so this is a
    real, not-invented convention to extend, not a new one).

**B. A shared click-inspector, one new function in
`galaxy_map_shared.js`, following the existing `_gmInit*` pattern:**

    function _gmInitEdgeInspector() {
      document.querySelectorAll('path[data-from][data-to]')
        .forEach(function(edge) {
          edge.addEventListener('click', function() {
            var key = edge.dataset.from + '|' + edge.dataset.to + '|' + edge.dataset.kind;
            var ev = window.GM_EDGE_EVIDENCE && window.GM_EDGE_EVIDENCE[key];
            _gmShowEdgePanel(edge.dataset.from, edge.dataset.to, ev);
          });
        });
    }

    `window.GM_EDGE_EVIDENCE` would be a real, per-PAGE JSON object
    (only the edges that page actually draws — never the whole
    project's evidence map shipped to every page, real payload-size
    discipline) emitted inline by each page's own Python generator,
    same "compute once, embed as data, cheap JS reads it" pattern this
    pipeline already uses everywhere else (never a runtime fetch()
    call, which `file://` blocks via CORS anyway — already confirmed
    and worked around once this session for the debloat pass).

    `_gmShowEdgePanel()` renders a small floating panel (reusing the
    established `.rdetail`/bubble-detail visual language already on
    every page, not a new component) with: the real explanation text,
    a `source` citation line (small, dim-colored, matching how every
    other evidence-linked element on these pages already cites its own
    source), and a real `<a href="{zoom_href}">Go there →</a>` link.

**C. What does NOT change:** R16 (no privileged L0 gateway), R22's
own existing "table first, bubble/edge follows" ordering, the River/
Dimension data model — none of this touches architecture, only adds a
real evidence lookup + one shared click handler on top of data that
already exists. This is intentionally a P0/P2-shaped slice (additive,
byte-identical-verifiable for every page that ISN'T touched, real and
useful even if P3 never happens) — not a P3-shaped one.
