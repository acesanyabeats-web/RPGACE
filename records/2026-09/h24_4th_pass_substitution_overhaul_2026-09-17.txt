REAL FIX 3 — curated groups are now authoritative, never fall through to
the loose heuristic
------------------------------------------------------------
Real root cause of the incoherent "shallot wants spring onion, but spring
onion (itself genuinely in stock, once Fix 2 landed) wants yellow onion"
chain: `_findSubstitute`'s curated-group check only ever returned early
on a real MATCH — if no real group member was in stock, it silently fell
through to the much looser aisle+shared-word heuristic below, which
matched spring onion against yellow onion purely because both contain
the bare word "onion." A curated group is a real, deliberate, hand-picked
answer (rule 7) — once one exists for an ingredient, it should be the
FINAL word, even when no real member happens to be in stock right now.
Fixed: `_findSubstitute` now returns null outright once it establishes
the ingredient belongs to ANY curated group, regardless of whether a real
match was found within it — never falls through to the heuristic for a
curated ingredient.

REAL FIX 4 — a real, GENERALIZED fix for the shared-generic-word class of
bug (found 4 separate times this session, not a one-off)
------------------------------------------------------------
Once Fix 3 was traced, the SAME failure shape kept recurring for
ingredients that had NO curated group yet: "soy sauce" -> "worcestershire
sauce" (shared "sauce"), "tamarind paste" -> "vanilla bean paste" (shared

still legitimately match via this word alongside a real identifying one
— "coconut milk" still correctly matches "full-fat coconut milk" via the
genuinely identifying shared word "coconut," verified directly).
