REAL EVIDENCE: Bookworm's chapter-reading flow, precisely
======================================================================

7 real render-states (not 5 — corrected by direct function-boundary
lookup, not assumed from line proximity), each currently spawning its
OWN fresh `dashDeck._popup()` call, stacking on top of whatever page is
showing underneath (including, after UI11, potentially on top of the
real `#page-bookworm` itself):

  _renderStructureFound   (TOC extracted from a new book)
  _renderChapterList      (all chapters, tap to jump)
  _renderChapterSummary   (a finished chapter's own summary)
  _renderChapterRead      (read a chapter's raw text)
  _renderAddChapterText   (paste in a chapter's text manually)
  _renderInsightReview    (review one extracted insight)
  _renderWaitingForNextInsight (background-analysis wait state)

Real, already-existing partial fix (W8, Aug 23): 4 of these 7 already
carry a "← Back to chapter list" button — but they're still popups
underneath that button, not real page navigation. This is the exact
"crammed interface" UI11/12/13 already fixed one level up (the
book-PICKER level) but never touched one level down (the actual
reading experience once inside a specific book).

Real, decisive fit against Alex's own confirmed criteria: this is a
record-detail view of a real record (a specific book, `bookworm_books`)
— you come back to the same book across many real sessions, exactly the
shape UI12's own Resume-button logic already assumes exists.

======================================================================
REAL SCOPED BUILD — Phase 1 (Bookworm)
======================================================================

1. All 7 render-states move INSIDE the existing real `#page-bookworm`
   page (built by UI11, currently hosting `bookworm-widget` only at its
   top/picker level) rather than spawning a new popup per state — the
   same "navigate within a real page" shape UI12 already uses at the
   picker level, extended one level deeper.
2. Real navigation replaces the current popup-stack: moving between
   chapter list → chapter read → insight review re-renders the SAME
   page content in place (matching this project's own `showPage()`/
   `.active` toggle convention), never a popup opening on top of a
   popup.
3. The existing "← Back to chapter list" buttons (W8) keep working —
   their real target becomes "re-render `#page-bookworm` at the chapter-
   list state" instead of "close this popup, the one underneath is the
   chapter list" (since there will no longer be a popup underneath).
4. Explicitly NOT touched: `bookworm`'s own module internals
   (`_analyzeChapter`, `_continueAnalyzingInBackground`, the real Supabase
   read/write shape) — this is purely a render-target change, same
   "pure internal-structure, zero functional change" discipline as G53.
