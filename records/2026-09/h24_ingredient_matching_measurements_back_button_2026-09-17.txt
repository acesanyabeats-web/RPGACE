REAL DIAGNOSIS FIRST (rule 4 — evidence before a fix, not a guess)
------------------------------------------------------------
Direct Supabase query on his own live `ingredients`/`pantry_stock` rows
found the real, single root cause behind nearly every symptom he
listed: RPGACE's ingredient resolution (`logic._resolveIngredient`/
`_resolveIngredientFull`) has always been an EXACT-STRING match — a
recipe asking for "lime" and Alex's own Current Stock entry "limes"
(both real, both meaning the same thing) became two wholly separate
`ingredients` rows, with real stock sitting on the row the recipe never
looks at. Confirmed for real, not guessed:
- `lime` (id 5e38d647, referenced by 2 real recipe_ingredients rows,
  zero stock) vs `limes` (id 5f998760, 2 Count in fridge, zero recipe
  references) — the exact "most insane" bug.
- `fresh coriander` (recipe wants, zero stock row) vs `whole coriander`
  (his real 200g fridge stock — the same bunch, different name).
- `beef shin` (recipe wants) vs `beef cuts with bone` (his real 1kg
  fridge stock — "ive got beef with bone, so can replace beef shin").
- `chicken stock` (recipe wants) vs `chicken stock cubes` (his real
  8-count pantry stock).
- `white cabbage` (recipe wants) vs `cabbage` (his real 1kg fridge
  stock).
- `garlic clove` (recipe wants) vs `garlic bulbs` (his real 5.5-count
  pantry stock — "garlic clove comes from a garlic bulb, so i have so
  many").
- `fresh ginger`/`ginger` (recipe wants) vs `ginger fresh` (his real
  150g pantry stock, same thing, reversed word order).

Separately, the schedule preview's "fresh coriander — have a substitute
in stock: ginger fresh" line was traced by hand through
`logic._findSubstitute`'s own heuristic: it shares the token "fresh"
with BOTH "ginger fresh" and "whole coriander," and the loop returns
whichever candidate the aisle list happened to iterate first — a real
qualifier word ("fresh") was being treated exactly like a real identity
word ("coriander"), so the wrong candidate won on iteration order alone.

REAL FIXES SHIPPED
------------------------------------------------------------
1. **The live "lime"/"limes" duplicate — merged for real, evidence-
   checked before touching anything.** Confirmed `limes` (5f998760) had
   zero recipe_ingredients/ingredient_prices/shopping_list_items
   references, only the 1 real pantry_stock row — safe, narrow,
   single-row UPDATE (reassign that pantry_stock row to `lime`'s real
   id) then DELETE the now-orphaned duplicate ingredient row. Verified
   post-merge: `lime` now correctly shows 2 Count in fridge.

2. **`logic._pluralVariant` + a real singular/plural fallback wired into
   BOTH `_resolveIngredient` and `_resolveIngredientFull` (rule 8 — the
   one real shared pattern, not two divergent copies)** — the actual
   preventive fix, so this exact bug class can't recur. On a cache-miss,
   a 2nd real lookup checks the trivial plural/singular variant (same
   len>3 trailing-s precedent `_normalizeUnit` already established)
   BEFORE ever minting a new `ingredients` row. Zero extra cost on the
   common already-exact-match path; one extra read only on what would
   already have been a real insert anyway.

3. **`_QUALIFIER_STOPWORDS`** — a real, curated list (fresh/dried/whole/
   ground/chopped/sliced/diced/minced/large/small/medium/frozen/fine/
   coarse/crushed/grated) excluded from `_findSubstitute`'s heuristic
   shared-token match. These words describe a PREPARATION, not what the
   ingredient actually IS — excluding them means only a genuine identity
   word (coriander, cabbage, chilli) can produce a heuristic match,
   fixing "fresh coriander → ginger fresh" for good (it now correctly
   finds "whole coriander").

4. **6 new curated `_SUBSTITUTION_GROUPS` entries, every one pulled
   directly from Alex's own verbatim examples above, never guessed**:
   beef shin/beef cuts with bone/beef stew meat/stewing beef; white
   cabbage/cabbage; garlic clove(s)/garlic bulb(s); ginger/fresh ginger/
   ginger fresh; fresh red chilli/red chilli/large red chilli/bullet
   chilli/bird's eye chilli; the existing coriander/cilantro group
   extended with "fresh coriander"/"whole coriander," and the existing
   chicken-stock group extended with "chicken stock cubes"/"vegetable
   stock cube"/"beef stock pot." Curated groups are checked FIRST in
   `_findSubstitute` and return immediately, so these correct matches
   now win before the heuristic ever runs — real, evidence-backed
   coverage, not an attempt to auto-detect every possible real-world
   pairing.

5. **`logic._fmtMeasurement(amount, unit)`** — real, shared cup/tbsp/tsp
   display formatter, Alex's own direct ask ("convert to cups and tbsp
   (1/16th of cup) so i can cook easier"). Uses ONLY the exact real
   VOLUME_TO_ML physics H19 already built (cup=240ml, tbsp=15ml,
   tsp=5ml — never an invented ratio, rule 7) to express a real ml/l
   amount as whole cups + whole tbsp + a real quarter-tsp-rounded
   remainder. A non-volume unit (g/kg/clove/Count/etc) passes through
   completely unchanged. Wired into both real display sites (rule 8):
   `ui._renderStepIngredients` (the schedule preview + the recipe
   card's own Method list, since H14 already shares this one function
   between both) and the recipe card's main "Ingredients" list.

6. **A real "← Back to Planned Cook" button on the Schedule Preview
   popup** — Alex's own direct ask. This popup is only ever reached from
   the Session Builder's own "📅 Schedule this cook" button (confirmed
   by grep — the one real caller), so that's the one real "previous
   slide" to return to; same established `pop.close(); reopen-the-
   prior-popup` pattern the Generate form's own "← Back to cook session"
   button already uses (rule 8). Going back leaves `self._session`
   completely untouched — only Accept clears it.
