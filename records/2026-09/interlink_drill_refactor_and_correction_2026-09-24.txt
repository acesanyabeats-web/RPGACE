THE REAL WORK — 3 pages refactored to expose a module-level DRILL
===========================================================================
Each of these 3 pages already had a working, correctly-rendering Map
view built from build_infra_drilldown() — the gap was purely that the
evidence/DRILL computation lived INLINE inside a function called once
per render, never as an importable module-level constant the shape
Oracle/Supabase/Decisions already expose.

1. galaxy_map_connectors.py — build_drilldown_section(conn) computed
   DRILL per-connector on every call, inside a loop over 3 connectors
   (Composio/Jina AI/Last.fm). Added a real module-level EVIDENCE dict
   (one key per connector, sourced from the SAME already-computed CALLS
   data, rule 8) fed into build_infra_drilldown() once — DRILL/ORPHANS
   now importable, zero change to the existing per-connector rendering
   logic (which still computes its own narrower evidence for its own
   real per-connector Map/Table toggle, unchanged).

2. galaxy_map_orchestrator_openmontage.py — a real, PRE-EXISTING rule-8
   duplication found and closed along the way: the evidence/DRILL
   computation for each unit (orchestrator_cc/openmontage_cc) was
   already computed TWICE independently — once inside
   build_shared_infra_section() for the real rendered Map view, once
   again inside main()'s own diagnostic print loop. Factored both into
   one shared _unit_evidence()/_unit_drill() pair, cached once per unit
   as module-level _DRILL_ORPHANS_BY_UNIT/DRILL_BY_UNIT dicts, and both
   real call sites now read from the cache instead of re-deriving. A
   real bug caught DURING this refactor, not shipped: DRILL_BY_UNIT's
   first draft stored only drill (discarding orphans) via a careless
   [0] index, which would have broken build_shared_infra_section()'s own
   unpacking the moment it was switched to read from the cache — caught
   by re-reading the function body before declaring the refactor done,
   fixed by keeping a separate full-tuple cache (_DRILL_ORPHANS_BY_UNIT)
   alongside the drill-only export (DRILL_BY_UNIT) river.py actually
   needs.

3. galaxy_map_oversight_sync.py — the exact same pre-existing
   duplication class found in (2): evidence/DRILL computed inline in
   build_shared_infra_section() AND again in main()'s diagnostic print.
   Factored into _oversight_evidence() + a module-level DRILL/ORPHANS
   pair, both real call sites now reuse it.

All 3 re-run standalone post-refactor and produce byte-identical real
counts to their pre-refactor output (confirmed by direct comparison of
each script's own printed diagnostic line) — the refactor changed only
WHERE the computation lives, never what it computes.
