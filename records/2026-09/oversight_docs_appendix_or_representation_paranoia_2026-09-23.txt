===========================================================================
COUNCIL OF 5 — THE REAL TENSION, BOTH SIDES
===========================================================================

FOR "load-bearing, not an appendix": CLAUDE.md is literally loaded as
Claude Code's own operating instructions every session — it doesn't
describe behavior, it IS behavior (the whole Tier/Judgment-Funnel system,
rules 1-17). Every session-start check and skill (/scope, /drift,
/cartographer) treats these docs as evidence sources gating real decisions.
SELF_KNOWLEDGE and oracle_module_anatomy directly shape what a real end
user reads. Deleting CLAUDE.md would visibly change how the very next
session behaves — an appendix could be deleted without changing anything.

FOR "an appendix wearing infrastructure's clothes": being READ doesn't mean
being CURRENT. The "Known landmines" section is itself a running list of
times the docs were caught lying about the system — repeatedly, over
months (vercel.json, 2 Python scripts, .claude/settings.json, and a GitHub
Action all independently referencing a deleted main.js for a week, found
one at a time by 4 separate accidents). Rule 16 exists because the project
had to formally admit "a doc can be made false by a change made somewhere
else entirely" as a STANDING, unsolved risk — if the representation were
proper by construction, rule 16 would be a one-time fix, not an ongoing
procedure it still is.

SYNTHESIS: these aren't really in tension — they're true of DIFFERENT
layers the project has been quietly conflating under one word. CLAUDE.md's
PROCESS layer (rules, decisions, the Judgment Funnel) is genuinely
load-bearing and doesn't go stale the way facts do — a rule from July is
still a valid rule in September. The Galaxy Map is a real, partially-
derived structural map with a known hole. But the FACTS-OF-STATE layer —
module counts, "what's built," Oracle's own self-knowledge, feature
status — is structurally an appendix: written once by whoever shipped the
thing, correct at that instant, then abandoned until an unrelated session
happens to re-check it. Nothing keeps facts current BY CONSTRUCTION — only
a discipline (rule 6) that keeps failing on exactly the artifact with the
least visible failure mode.

/drift VERDICT
===========================================================================
VERDICT: DRIFTED. "Oversight docs give RPGACE and Claude Code the best
context of what is done" is not a standing property — it is intermittently
true, restored by manual sweeps, degrading continuously between them.

BASIS: PROVISIONAL, not ratified. Rule 6 states the intended invariant but
nothing mechanically enforces it; the update-logging-system skill is a
checklist, and its own text already says a checklist doesn't enforce
itself — an honest, pre-existing admission of a weak basis.

GRADE: MATERIAL. Nothing has broken in production from this (SELF_KNOWLEDGE
fails open — a wrong answer, not a crash), but real, substantial,
user-visible drift accumulated for a month with nobody tracking it until
this question forced the check.

===========================================================================
DIRECT ANSWER
===========================================================================
No, not just an appendix — the process/governance layer (CLAUDE.md's own
rules, the Judgment Funnel, session-start checks) is genuinely load-bearing
infrastructure this session runs on. But no, it also is not a proper,
continuously-accurate representation of "how the total system is connected
and coded" — the one artifact that would need to be that (Oracle's own
self-knowledge) was silently wrong for a month, and the parts that ARE
currently accurate are accurate by luck of recent manual attention, not by
design. Honest name for what exists: a governance layer that's genuinely
load-bearing, wrapped around a facts layer that's structurally an
appendix — accurate only immediately after someone checks, with no standing
mechanism that notices when it stops being accurate in between checks.
