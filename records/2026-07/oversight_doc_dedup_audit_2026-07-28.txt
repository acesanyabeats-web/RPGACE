COUNCIL OF 5 — diagnosis
════════════════════════════════════════════════════════════════
Technical risk: none — this is a documentation change, zero application
code touched.
Scope/cost: real. Three docs (CLAUDE.md's Current State,
interconnection_map.md, patch_notes.html) were independently narrating
the same events in full prose — every incident got written up to 3
times. This is the actual mechanism behind "lost sight of what to
write down."
Maintainability: each doc has a different, sensible PURPOSE
(patch_notes.html = full narrative changelog; interconnection_map.md =
structural touchpoints, present-tense; CLAUDE.md = operational rules +
durable current-state facts; system_flow_map.md = diagrams + truth
table) — the drift wasn't that any doc's purpose was wrong, it was that
narrative content kept leaking into docs whose job was NOT narrative.
UX (for Alex/future sessions reading these): tripled maintenance cost
with no corresponding benefit — reading interconnection_map.md for "what
talks to what" required wading through the RLS-flip incident story
already fully told in patch_notes.html.
Why NOT to prune: real risk of losing load-bearing facts (open items,
landmines, still-unconfirmed things) by cutting too aggressively. Named
explicitly as the thing to check for before any cut.

════════════════════════════════════════════════════════════════
/DEBATE — what should stay as a "constant agenda," what gets cut
════════════════════════════════════════════════════════════════
FOR keeping full narrative in CLAUDE.md/interconnection_map.md: easier
to read one doc instead of cross-referencing patch_notes.html.
AGAINST: this is precisely what caused the drift Alex is reporting —
narrative duplicated across docs means any doc can silently go stale
relative to the others, and there's no single source of truth for "what
actually happened when."
Resolution: patch_notes.html is the ONE place incident narrative lives.
CLAUDE.md's Current State collapses to durable-fact bullets (still-open
items, standing rules, things a future session needs to know without
re-deriving) with a pointer to patch_notes.html for the story.
interconnection_map.md returns to its own stated purpose — current
architecture only, present tense, no dates in section headers unless
the date itself is load-bearing (e.g., "confirmed July 24" as a
verification timestamp, not a build-narrative label).
