FREE-FOR-ALL DEBATE (each competitor picks 2 problems)
A (data-first): (1) Show only rows with something in them. An empty "0 decisions due" row is noise. (2) 523
  pending jargon is a wall; show it as "Review 10 jargon terms", a bite-size daily dose, not the raw total.
B (navigation): (1) Left nav needs to open popup modules (cards) as well as pages: entries carry either page or
  card, card routes through dashDeck._navOpenCard so N1 history and the domain crumbs keep working. (2) NAV_DOMAINS
  is the single domain source: the nav groups and the popup sibling chips read the same map (rule 8), and
  wishlist moves to Habits there so both agree.
C (conjure data): (1) Record a "trail": every page shown and every card opened writes {kind,key,label,at} to
  localStorage (last 8, dashboard excluded). Cheap, zero schema, powers "Continue". (2) Add real deep links
  where they already exist: in-progress book via bookworm._openBook(id), latest recipe via
  cookingOracle._loadSavedRecipe + _showRecipeCard.
D (skeptic, why NOT): (1) Losing the card grid loses the glance numbers. Answer: each useful number moves into
  a Due row with its action. Nothing that was actionable disappears. (2) On a phone, the nav is behind the
  hamburger. Answer: the landing sections themselves link to the work, and the hamburger is one tap. Alex asked
  for left nav only, so no second chip grid (that would recreate the duplicate).
E (Oracle): (1) Ask Oracle from the dashboard should reuse the real chat input: open the Oracle page, put the
  text in #chat-input, call sendChat(), with no second chat mechanism. (2) Morning Brief opens the existing
  _openMorningBrief popup, which already carries recall + daily-life sections.

RISKS (/paranoia)
- _refreshGlance is called from 3 other places; keep the name, rewrite the body for the landing page.
- #dd-deck guard: _inject returns early if #dd-deck exists. Keep the same id for the landing wrapper.
- Shared-link queue needs Alex's PC. Say that in the row, never imply it is being analysed.
- No new tables, no new api files, no Oracle calls on the dashboard (works when Oracle is down, per the
  Aug 6 Morning Brief insight).
- Boot can run before config.init() sets RPGACE.sb: guard every loader, retry, and refresh on login
  (caught in testing: unguarded gym/recall loaders threw and left the page on "Loading...").

DECISION
Build: grouped left nav (all 14 cards + all pages, 7 domains), landing dashboard with Today / Due / Continue /
Morning Brief + Ask Oracle, the trail recorder. Remove the card grid and the old "Needs you now" block (folded
into Due).
