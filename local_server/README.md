# RPGACE Local Server

Real infrastructure that runs on Alex's own Windows machine (`%USERPROFILE%\RPGACE`, i.e. `C:\Users\acesa\RPGACE\`) — **not deployed, not hosted, not always-on**. Brought into this repo Aug 27 2026 per Alex's own confirmed ask ("bring the source into this repo, like `scripts/` already works") so a Claude Code session can finally read/edit it directly, rather than it being an invisible black box every session had to reason about from the outside.

**This does not change how it runs.** It still only exists when Alex double-clicks a `.bat` file on his own desktop. No new hosting, no new spend, no new public exposure — `rpgace_core.js`'s `LOCAL_SERVER` constant is still hardcoded to `http://localhost:7842`, reachable only from a browser on the same machine.

## Files

- **`start_server.bat`** — launches `local_server.py`, the actual HTTP server RPGACE's client code talks to on port 7842 (`/reports`, `/watchlist`, `/push-to-supabase` — see `rpgace_core.js`'s `fetchFromLocal`/`fetchWatchlistFromLocal`/`pushLocalToSupabase`).
- **`intel.bat`** — launches `rpgace_intel.py <url>`, the actual Content Intelligence analysis script ("paste a URL, analyse any video" — CLAUDE.md's own "Intel script").
- **`local_server.py`** — real source, brought in Aug 27 2026. An `http.server` on port 7842 serving `/reports`/`/watchlist`/`/stats`/`/push-to-supabase` (reads local JSON from `~/RPGACE/strategy/intel_*.json`, up to 50 most recent) plus a background poller draining a real `intel_jobs` Supabase queue and dispatching to `rpgace_intel.process_url`.
- **`rpgace_intel.py`** — real source, brought in Aug 27 2026. The actual analysis pipeline: yt-dlp download → Whisper transcription → ffmpeg frame extraction → Claude Vision + Claude text analysis (a direct `api.anthropic.com` call, its own separate API key at `~/RPGACE/.anthropic_key` — NOT the same key/path as RPGACE's own `/api/oracle.js` proxy) → deletes the video → saves a report locally and pushes `intel_reports`/`encyclopedia`/`intel_watchlist` rows to Supabase directly.

**Real findings from reading the actual source (not assumed), Aug 27 2026:**
- Both files hardcode Supabase's own `sb_publishable_...` key — checked against `rpgace_core.js`, it's the byte-identical key already public in this same repo (a Supabase *publishable* key, meant to be client-exposed by design). Not a new secret, no rotation needed for this one.
- **TLS certificate verification — FIXED, same day.** Both `local_server.py` and `rpgace_intel.py`'s own inline copy disabled certificate verification entirely (`ssl.CERT_NONE` + `check_hostname=False`) — a real MITM exposure. `rpgace_intel.py`'s own comment on its copy ("Windows SSL fix — bypass cert verification") confirmed this was a workaround for Windows Python's missing system CA store, not a deliberate tradeoff. Fixed with `certifi`'s own bundled CA root store (auto-installed via pip on first run if missing, same pattern already used for yt-dlp/whisper), applied identically to both files. Verified: the resulting context has `check_hostname=True`/`verify_mode=CERT_REQUIRED` (real, confirmed — a live round-trip against Supabase couldn't complete from this sandboxed session's own outbound proxy, same standing limitation as elsewhere in this project; that's an environment constraint, not a gap in the fix). Commit `fe11db1`.
- **`/push-to-supabase` had zero deduplication and zero deletion-awareness — FIXED, same day.** It used to blindly re-POST every local `intel_*.json` file with no check for "does Supabase already have this" or "was this deleted," a real, confirmed (not theoretical) duplicate-row risk on every re-sync, and the exact mechanism that resurrected a deleted report (see the Aug 27 2026 "delete doesn't stick" fix). Fixed with a new `norm_url()` (mirrors `intelDedup.normUrl` behaviorally, verified against the same edge cases) plus 2 real pre-push checks: an existing `intel_reports` row for the URL skips it (fixes duplicates), a pending `intel_reanalysis_pool` marker at least as new as the local file's own date skips it too (fixes resurrection) — a genuinely newer local re-analysis still gets pushed through. `rpgace_intel.py`'s own direct encyclopedia push gained the matching `source_url` fix (see below). Commit `558e905`.
- `~/RPGACE/.anthropic_key` (a plaintext API key file this script creates/reads) is never in this repo — confirmed by direct read, nothing in the uploaded source contains a real key value. `.gitignore` in this folder defensively excludes it and the other runtime-data folders (`intel/`, `strategy/`, `transcripts/`, `inbox/`, `processed/`) in case `HOME` is ever pointed at a git checkout.

## Cloud runner (Oct 11 2026)

The same pipeline also runs on GitHub Actions (`.github/workflows/intel-queue.yml` → `scripts/intel_cloud_runner.py`, which imports this folder's `rpgace_intel.py`), every 10 minutes, using the repo secret `INTEL_ANTHROPIC_KEY`. A job is only taken if it is still `queued`, so this laptop server and the cloud runner can both run. YouTube blocks cloud servers, so YouTube links are left for this laptop unless a `YT_COOKIES` secret exists. `local_server.py` updates yt-dlp and Deno on every start, and saves a failed job's real reason in `intel_jobs.error`. **VW-0 (Oct 20 2026): the laptop runs the code from a Git copy of this repo, `%USERPROFILE%\RPGACE-code` (sparse: `local_server/` + root files), and `start_server.bat` runs `git pull --ff-only` before every start** (warns and runs the existing copy if Git is missing or the pull fails), so the laptop can't drift from the repo again (it had: an Oct 11 copy that predated realms). A first version downloaded the files with curl and ran them; AVG's Behavior Shield blocked that as IDP.Generic, so it was replaced by Git. `local_server.py` imports `rpgace_intel`/`intel_common` from its own folder; data, reports and `.anthropic_key` stay in `%USERPROFILE%\RPGACE`. **VW-1 (Oct 20 2026)**: the analysis reads the whole video — Whisper's timed segments (`[m:ss]` lines, saved in `transcripts/`), the whole transcript (filler lines dropped by the cheap model only over 6000 words, kept lines word for word), 8 frames spread over the whole video, and a frame question that follows the picked realms. `intel_common.py` holds `ANALYSER_VERSION` (bump it whenever the analysis changes; stored on `intel_reports.analyser_version`), the one-runner claim (`status=eq.queued`, `started_at`, `taken_by`) and the 2-hour stuck-job reset. Because the .bat lives in the Git copy, `git pull` updates it too (the new version is used from the next start).

## Real, standing constraint

Both `.bat` files `cd /d "%~dp0"` — they run the `.py` files next to them, so they must be started from inside the Git copy (`%USERPROFILE%\RPGACE-code\local_server`). Old `.bat`/`.py` copies left in `%USERPROFILE%\RPGACE` are no longer used.

## The real residual risk this was meant to close — CLOSED, same day

The Aug 27 2026 "delete doesn't stick" fix (`records/2026-08/delete_doesnt_stick_tombstone_ceo_spec_2026-08-27.txt`) named an honest, unclosed gap: `local_server.py`'s own `/push-to-supabase` handler was opaque to every prior Claude Code session. Bringing the real source in confirmed that gap was genuine, not hypothetical — and it's now fixed (see "Real findings" above and commit `558e905`), verified via 13 real isolated-test assertions covering `norm_url()`'s URL normalization and the full push-handler decision logic (existing-row skip / older-than-deletion skip / newer-passes-through / brand-new-passes / same-URL-twice-in-one-batch dedup).
