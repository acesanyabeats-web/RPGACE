# /cartographer — the real mapping-and-cross-talk discipline

Named and built Aug 13 2026, real Alex ask, folded into the already-
ratified "RPGACE Total Systems Galaxy Map" `/CEO` plan (extends G6/G7/G8,
adds a new item for Consumer/Developer tiering — see
`records/2026-08/galaxy_map_ceo_loop1_spec_paranoia_2026-08-13.txt` for
the full compiled spec, real open forks, and paranoia/drift/restructure
scrutiny this skill itself was built under).

His own words, verbatim, on why: *"i would like all externals and
rpgace self-awareness to talk to each other via these tables and docs
to update what new, whats old, and use trckle down/up to also cause
updating where needed to be flagged to me too, expanding my original
idea further."* — the "original idea" being G7's trickle-down/up
suggestion-and-error report system; this skill is that idea, formalized
and given a real invocation point, plus his own further expansion: it
must also surface to HIM directly, not just log for the next AI session
to maybe notice.

## What this skill actually does, in order

1. **Ground against `system_map_spec.md`.** Before mapping anything —
   answering a "what changed" question, regenerating graphify/Obsidian,
   or checking a real Total-system update for downstream effect — read
   that doc's real hierarchy/tagging/interaction-type rules first. It
   states the METHODOLOGY; `scripts/graphify_river_group.py`'s own
   Python tables (`RIVER_MODULES`/`RIVER_FLOWS`/`EXTERNAL_CONNECTORS`/
   `INTERACTION_TYPE_LABEL`) hold the real live DATA that methodology
   governs — never re-derive the rules from scratch, and never treat
   `system_map_spec.md` as itself the live data source.

2. **Identify the real change's level.** Galaxy, river, module/function,
   or connector edge — per `system_map_spec.md` §1. A change that
   doesn't fit cleanly into this hierarchy (most day-to-day content
   edits) doesn't need this skill at all — it stays on the normal
   `update-logging-system` path.

3. **Run the trickle-down/up cross-reference.** Check the change against
   this map + Tier (b) truth docs (`interconnection_map.md`/
   `system_flow_map.md`/`ai_tooling_and_rules_map.md`) for real
   integration friction — does an existing description elsewhere now
   read stale because of this change, either upstream (something this
   change depends on) or downstream (something that depends on this
   change)? A real finding here is graded the same MINOR/MATERIAL/
   CAPTURED vocabulary `/drift` already uses, not a separate scale.

4. **Surface real findings to Alex directly** — his own explicit
   expansion of the original idea. A MINOR finding gets fixed inline and
   noted in the session's own report; a MATERIAL or CAPTURED finding
   gets stated plainly in chat, not just logged to a table for a future
   session to maybe surface. **Real, honest scope note**: the recommended
   `system_map_flags` table (see the same-day record file) is where
   these get tracked so nothing gets lost between sessions either — the
   direct-to-Alex surfacing and the persistent tracking are both real,
   not a choice between them.

5. **Tag Consumer/Developer visibility** on any new artifact this
   process touches, per `system_map_spec.md` §7 — `developer` (Alex-only
   oversight/dev-process detail) or `consumer` (safe for a future
   end-user-facing product). **Not yet applied retroactively anywhere**
   — this step only tags NEW artifacts going forward until Alex
   confirms the real retroactive tagging pass (a genuinely separate,
   larger piece of work, flagged not guessed at).

6. **Invoke the sharper skills only where the finding's own shape calls
   for them** — `/drift` for a real goal-vs-baseline check, `/paranoia`
   for something Alex wants maximally scrutinized before acting on,
   `/misunderstanding` ONLY if Alex himself signals a real disconnect
   (never self-triggered, same boundary that skill already has). This
   skill is the grounding/cross-talk layer these get invoked FROM, not
   a replacement for any of them.

## How this wires into `/CEO`

Per Alex's own explicit ask ("update into ceo so it happens when ceo
mode is on"): while a `ceo_plans` row is `status='active'` (Grounded
Mode live, per that skill's own section), any real change touching a
plan item ALSO runs Step 3-4 above — the trickle-down/up cross-
reference — as part of that per-prompt check, not a separate ritual.
See `.claude/skills/CEO/SKILL.md`'s own Grounded Mode section for the
exact wiring point.

## Real, honest scope — what this skill does NOT do

- It does not auto-fix a real MATERIAL/CAPTURED finding on its own —
  same Tier-3 boundary as everywhere else in this project; a real
  integration-friction finding gets surfaced and decided, never
  silently patched.
- It does not replace `update-logging-system`'s own artifact-type
  checklist for ordinary content updates — this is specifically the
  cross-talk/trickle layer for changes that touch the real mapping
  hierarchy itself.
- It does not retroactively tag every existing doc/table Consumer/
  Developer — that's real, separate, future work, not silently done
  as a side effect of this skill existing.
- The `system_map_flags` table it references is a real, compiled
  RECOMMENDATION as of Aug 13 — not yet built. Check the same-day
  record file for its proposed schema before assuming it exists.
